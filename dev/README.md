# dev —— 本地调试脚本

这个目录放**只在本机用、不入库**的调试脚本。

## 为什么单独放一个目录

以前 `test.py` / `test_main.py` 直接躺在项目根目录，和 `Lib.py`、`README.md` 混在一起，
看起来像是交付入口。实际上它们是随手改的调试脚本，`.gitignore` 也一直忽略它们。

挪到这里之后：

- 根目录只剩「源码 / 文档 / 工程配置」三类东西，一眼能看出项目结构；
- 调试脚本集中放，不会和正式的 `tests/`（pytest 用例）混淆。

## 现有脚本

| 文件 | 用途 |
|---|---|
| `test.py` | 临时验证单张模板图能否识别、单个界面动作能否点击。改一行跑一次，是最常用的调试入口 |
| `test_main.py` | 单独跑某个 `MainTask_*` 入口，跳过 GUI，用来复现任务流程问题 |

两者都会**真的操作游戏窗口**（找窗口、置前、点击），运行前确认：

1. 模拟器已启动、窗口标题含账号名（`master` / `slaves`）；
2. 当前没有别的事情要用鼠标键盘。

## 注意

- **这两个文件不入库**，改坏了直接从 git 历史里找不回来，重要改动请另存一份。
- `.gitignore` 里的 `test.py` / `test_main.py` 是不带路径的规则，会匹配任意层级，
  所以 `dev/test.py` 同样被忽略。
- **不要在 `dev/` 里创建 `test_*.py` 命名的文件**：`test_main.py` 恰好符合 pytest 的
  `python_files = test_*.py` 规则，虽然 `pyproject.toml` 里 `testpaths = ["tests"]`
  限定只收 `tests/`，但手动执行 `pytest dev/` 会把它当成测试文件收集并**执行模块级代码**
  （即真的去操作游戏窗口）。要验证调试脚本，直接 `python dev/test_main.py`。

## 与 `tests/` 的区别

| | `tests/` | `dev/` |
|---|---|---|
| 是否入库 | ✅ 入库 | ❌ 忽略 |
| 是否碰游戏窗口 | ❌ 纯逻辑，秒级 | ✅ 会真实操作 |
| 什么时候跑 | 每次改代码后 | 调试具体问题时手动跑 |
| 跑法 | `python -m pytest` | `python dev/xxx.py` |
